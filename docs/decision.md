# 설계 및 정책 결정 기록

이 문서는 구현 방식과 사용자 관점 정책의 결정 상태 및 근거를 관리한다. 정책을 확정하면 관련 requirements·architecture 문서와 README를 함께 갱신한다.

## 결정됨

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 내부 저장 형식 | CSV를 사용한다. 거래·카테고리·예산은 각각 별도 CSV 파일에 저장한다. | 파일 기반 저장 요구사항을 단순하고 일관되게 충족한다. |
| 최신순 목록·검색과 스트리밍 | 저장 파일을 최신 날짜 우선 순서로 유지하고, 저장 순서를 그대로 순회해 제너레이터로 제공한다. 같은 날짜는 등록 순서를 유지하며 검색 필터는 순회 중 적용한다. | 전체 파일을 메모리에 올려 정렬하지 않고 최신순과 스트리밍을 함께 만족한다. |
| 정책 결정 기록 위치 | 미결정 및 확정된 설계·정책 결정과 근거를 이 문서에서 관리한다. | 정책의 단일 출처를 둔다. |
| 데코레이터 문서 책임 | 최소 구현 조건은 requirements, 구현 위치와 기술적 주의점은 architecture에서 다룬다. | 인수 조건과 구현 방법의 중복을 줄인다. |
| 테스트 문서 책임 | 테스트 케이스, 명령 및 최종 검수 기준은 testing에서 관리한다. requirements에는 기능 완료 조건만 둔다. | 요구사항과 검증 절차의 반복을 줄인다. |
| 빈 카테고리 저장소 | 시작 시 기본 카테고리 `FOOD`, `TRANSPORTATION`, `SHOPPING`, `HOUSING`, `ENTERTAINMENT`, `OTHERS`, `SALARY`, `SIDEINCOME`을 자동 생성한다. | 최초 거래 등록 전에 기본 지출·수입 카테고리를 제공한다. |
| 카테고리 이름 | 앞뒤 공백을 제거해 저장하고 비교한다. 중복 판정 시 대소문자를 구분하지 않는다. | 공백 및 대소문자 차이로 중복 카테고리가 생기지 않게 한다. |
| 사용 중 카테고리 삭제 | 해당 카테고리를 참조하는 거래가 있으면 삭제를 차단한다. | 기존 거래의 카테고리 참조 무결성을 유지한다. |
| 같은 월 예산 재설정 | 해당 월의 기존 예산을 새 금액으로 갱신한다. | 월별 예산 레코드가 하나로 유지되도록 한다. |
| 가져오기 행 오류 | 유효한 행만 반영하고, 오류가 있는 행은 건너뛴다. 각 오류의 CSV 행 번호를 사용자에게 출력한다. | 유효한 데이터의 가져오기를 계속하면서 잘못된 행을 식별할 수 있게 한다. |
| 가져오기 중복 | 날짜·금액·카테고리·타입·메모가 모두 일치하는 거래는 중복으로 보고 가져오지 않는다. 태그는 중복 판정에 포함하지 않는다. 기존 거래 및 같은 CSV에서 앞서 처리한 행과 비교한다. 사용자 재확인 없이 건너뛰고, 가져오기가 끝난 뒤 중복 행이 있었음을 알린다. | 중복 거래를 방지하면서 가져오기 중 사용자 입력을 요구하지 않는다. |
| 거래 날짜 동률 정렬 | 날짜가 같은 거래는 입력(등록) 순서를 유지한다. | 같은 날 거래의 입력 순서를 보존한다. |
| 거래 수정 인터페이스 | 옵션 기반과 대화형 수정을 모두 지원한다. | CLI 자동화와 직접 입력을 모두 허용한다. |
